# Architecture

- **Rust/Tauri host:** Owns the hidden/revealed window, tray and keyboard hook. `tauri-plugin-single-instance` is registered first; its activation callback reveals and focuses the existing main window.
- **Hotkey:** The low-level hook only tracks configured modifier and trigger. On activation an action worker reads the selection first, then explicitly shows/focuses the window and emits the capture result. The frontend places it beside the selection/cursor, clamps it to the corresponding monitor work area, and displays captured text.
- **Thai analysis:** `kham-core` provides offline sentence segmentation and newmm word segmentation. The vocabulary overlay is loaded from SQLite at startup. The English/romanization database lookup is separate from segmentation and separate from translation.
- **SQLite:** `assets/learner.sqlite` is a generated subset of ThaiReader v42 (word entries, senses, examples, source rows), plus a clearly distinguished project-provided sample. On first launch the app copies it to the platform app-data folder as `phasaforge.sqlite` and creates a separate `corrections` table. User data therefore survives installer upgrades. Regenerate the bundled seed with `python scripts/build_learner_db.py` after changing the attributed TSV snapshot.
- **Translation:** Speech recognition, text translation, and speech synthesis are independent paths. Azure F0 is the established primary sentence translator; its key is read from Windows Credential Manager. Practice currently calls Azure F0 directly after recognition as a temporary diagnostic, bypassing the saved provider choice. The intended architecture is to use the persisted provider configuration, with Azure F0 primary and optional local Ollama/offline choices, without coupling translation to either speech engine. Provider choices are persisted in WebView local storage. Ollama uses native Rust HTTP requests to the local `OLLAMA_HOST` (default `127.0.0.1:11434`). Startup discovery only reads Ollama's API and model manifests. It does not load a model, alter `OLLAMA_MODELS`, or restart the service; selecting Local Ollama and saving settings remains the manual load path. `api/pull` downloads only a user-entered model after the user presses Download. No text is sent to Thai2English.
- **Speech:** Windows WinRT is preferred when an installed Thai voice is available, followed by a Thai Web Speech voice; local Meta MMS-TTS Thai is the final automatic fallback and can also be selected explicitly. MMS uses CPU inference and downloads its optional model separately. Microphone practice records and replays a browser media blob and releases microphone tracks on stop. Optional Thai ASR is prepared on demand in an isolated Python environment under app data. After Stop, Web Audio decodes and resamples the in-memory recording, Rust stages a temporary 16 kHz WAV, and a short-lived sherpa-onnx CPU process transcribes it with the int8 Thai Zipformer model. Whisper.cpp was the initial proposal; sherpa-onnx was the implemented replacement and remains the selected backend. The temporary WAV is removed after the attempt; no audio is uploaded or retained by the recognizer. This model is offline, so interim words during recording are not available. No pronunciation or tone score is produced.
- **Frontend:** Vite, TypeScript and plain DOM/CSS. The Settings view is an internal scrollable page. User-facing messages expose unavailable providers and missing data instead of silently substituting content.
- **Window placement:** Existing physical-pixel monitor/work-area calculation is retained. The custom title bar remains draggable; fixed dimensions match the 640×480 concept.
- **Assets/data:** UI artwork is the supplied project artwork. The learner data license is separate from MIT app source and is reproduced in `reference-data/thaireader-v42/THAI-LEXICON-LICENSE.md`. No media-library files are included.
